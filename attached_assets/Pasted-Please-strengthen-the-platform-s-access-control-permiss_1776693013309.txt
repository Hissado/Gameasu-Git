Please strengthen the platform’s **access control, permissions, user onboarding, and administrative management** to ensure the system is secure, well-structured, and easy to manage.

The goal is to make sure users only access what they are authorized to see, while giving admins full and controlled authority over organizational structure, permissions, and platform management.

## 1. Project-based access control
Please ensure strict project-based access rules are enforced across the platform:

- Each user must only be able to view and access the projects assigned to them
- Users must not be able to see, open, or interact with projects that are not assigned to them
- Each user must only be able to view, interact with, and chat with team members linked to the same assigned project(s)
- Group chats, direct chats, files, project workspaces, and related collaboration areas must be restricted based on:
  - project assignment
  - department
  - user role
  - permission level
- Admins and authorized managers should be able to manage these access rules easily from the admin panel

## 2. Role-based access and permissions
Please implement a robust **role-based access control (RBAC)** system.

The system should allow admins to:

- create, edit, and delete user roles
- define what each role can access
- assign permissions by role
- control which modules, sections, projects, files, chats, settings, and actions each role can access
- manage permissions in a structured and user-friendly admin interface

Please ensure:
- role changes are reflected immediately across user access, assignments, and project visibility
- critical permission changes include confirmation or safeguard steps
- only authorized admin roles can manage permissions

## 3. Department management
Please add full **department management** to the admin panel.

Admins should be able to:
- add departments
- edit departments
- remove departments
- assign users to departments
- link departments to projects, roles, or workflows where relevant

Please ensure:
- department changes are reflected properly across user assignments and permissions
- deleting a department includes appropriate confirmation and safeguards
- department structure is cleanly integrated into onboarding, user management, and access control

## 4. User roles during invitation and onboarding
Please make the **user creation and invitation workflow** more structured and secure.

When an admin creates or invites a user, the admin should be able to:
- assign a role immediately
- assign a department
- assign project access where relevant
- define the user’s initial permissions or access scope if needed

Please ensure:
- roles are clearly selectable during the setup flow
- the onboarding workflow is smooth, secure, and easy for admins to manage
- user setup reflects the organizational structure of the platform from the start

## 5. Email invitation system
Please ensure invited users automatically receive a professional and reliable email invitation.

The invitation email should clearly include:
- the invitation link
- login instructions
- next steps
- any temporary credentials if applicable

Please make sure:
- email delivery is reliable
- the message looks professional
- the invitation process is secure
- admins can track invitation status if possible
- the system handles resend invitations cleanly if the user did not receive the original email

## 6. First-login password reset
Please enforce a mandatory password reset for first-time users.

If a user logs in with a default or temporary password:
- they must be forced to change it immediately
- they must not be allowed to continue using the platform until they set their own secure password

Please ensure this process is:
- secure
- user-friendly
- aligned with good access control practices

## 7. Admin authority over platform content
Please make sure authorized admins have full management control over the platform.

Admins should be able to create, edit, manage, and delete:
- projects
- files
- folders
- chats
- workspaces
- departments
- roles
- permissions
- users
- and other related platform records where appropriate

Please ensure:
- these actions are restricted to authorized admin roles only
- permanent deletion actions include confirmation prompts and safeguards
- critical deletions are handled carefully and professionally
- soft delete or archive logic is considered where appropriate instead of immediate permanent deletion

## 8. User administration
Please give admins full ability to manage user accounts.

Admins should be able to:
- create users
- invite users
- edit user details
- assign or change roles
- assign or change departments
- assign or change project access
- deactivate users
- delete users when necessary

Please ensure:
- only authorized admins can delete users
- deletion includes a confirmation step
- the system properly handles the user’s assigned projects, tasks, files, permissions, and chat history when the account is removed
- user removal does not break data integrity across the platform

## 9. Permission-sensitive collaboration areas
Please make sure collaboration features respect the permission model across the platform.

This includes:
- direct chat
- group chat
- project chat
- file sharing
- project workspaces
- department spaces
- shared records
- settings visibility
- task collaboration
- project member visibility

Users should only be able to access collaboration spaces that are relevant to:
- their role
- their department
- their assigned projects
- their permission level

## 10. Safeguards and security
Please include appropriate safeguards for all sensitive actions, such as:
- delete confirmations
- warning modals for irreversible actions
- protection against accidental removal of critical data
- role/permission restrictions for destructive actions
- clean handling of dependencies when deleting users, roles, departments, or projects

Where relevant, include:
- audit logs
- activity history
- admin-only critical actions
- archived/deactivated states instead of hard deletion

## Goal
The overall goal is to make the platform’s **user management, onboarding, access control, role management, department management, and admin governance** much more secure, professional, scalable, and well-structured.

The final result should ensure that:

- users only see what they are allowed to see
- project access is tightly controlled
- chats, files, and collaboration are properly restricted
- admins can fully manage users, departments, roles, and permissions
- onboarding is secure and professional
- invitation emails work reliably
- first-time login security is enforced
- deletion and sensitive actions are protected by proper safeguards
- the platform is ready for real organizational use at scale
