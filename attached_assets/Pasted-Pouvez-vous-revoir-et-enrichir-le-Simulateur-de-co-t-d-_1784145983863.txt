Pouvez-vous revoir et enrichir le Simulateur de coût d’un collaborateur dans le module Ressources Humaines de Gameasu en utilisant comme référence le fichier Excel joint : « TROUVER LE SALAIRE BRUT À PARTIR DU NET » ?

Objectif

Je veux transformer le simulateur actuel en un véritable outil professionnel de simulation salariale permettant de calculer :

1. le salaire brut à partir du salaire net souhaité ;
2. le salaire net à partir du salaire brut ;
3. le coût total réel du collaborateur pour l’employeur ;
4. l’impact d’une embauche, d’une augmentation, d’une promotion, d’une prime ou d’un bonus sur la paie, le budget et la trésorerie.

Le simulateur doit être réaliste, pédagogique, bidirectionnel et configurable selon les règles sociales et fiscales applicables dans le pays de l’organisation.

⸻

1. Intégrer deux modes de simulation

Ajouter un sélecteur visible en haut du simulateur :

Mode A — Du net vers le brut

L’utilisateur renseigne le montant que le collaborateur doit effectivement percevoir.

Exemple :

Salaire net souhaité : 120 000 FCFA

Le système calcule automatiquement :

* le salaire brut correspondant ;
* les cotisations salariales ;
* la base imposable ;
* l’IRPP ;
* le salaire net de vérification ;
* les charges patronales ;
* la provision pour congés payés ;
* le coût total employeur.

Mode B — Du brut vers le net

L’utilisateur renseigne la rémunération brute complète.

Le système calcule automatiquement :

* les cotisations salariales ;
* la base imposable ;
* l’IRPP ;
* les autres retenues ;
* le salaire net imposable ;
* le salaire net à payer ;
* les charges patronales ;
* le coût total employeur.

Le changement de mode doit recalculer immédiatement tous les résultats.

⸻

2. Décomposer correctement le salaire brut

Le salaire brut ne doit pas être limité à un seul montant global.

Il doit pouvoir être composé de plusieurs éléments :

Éléments fixes

* salaire de base ;
* sursalaire ;
* indemnité de fonction ;
* indemnité de logement ;
* indemnité de transport ;
* autres indemnités fixes.

Éléments variables

* prime de rendement ;
* prime d’ancienneté ;
* prime de responsabilité ;
* prime exceptionnelle ;
* commissions ;
* heures supplémentaires ;
* bonus ;
* rappel de salaire ;
* avantages en nature ;
* autres éléments variables.

Pour chaque élément, permettre de préciser :

* montant ;
* périodicité ;
* soumis ou non aux cotisations sociales ;
* imposable ou non imposable ;
* permanent ou exceptionnel ;
* inclus ou non dans le salaire brut ;
* compte comptable associé ;
* centre de coût ou projet concerné.

⸻

3. Reprendre la logique du fichier Excel

Le fichier joint utilise notamment les éléments suivants :

* salaire net souhaité ;
* nombre de personnes à charge ;
* calcul itératif du salaire brut ;
* cotisation salariale ;
* détermination de la base imposable ;
* calcul progressif de l’IRPP ;
* vérification du salaire net obtenu ;
* charges patronales ;
* provision pour congés payés ;
* coût total employeur.

Merci de reprendre cette logique dans Gameasu, mais de la rendre plus robuste, transparente et configurable.

Exemple de résultat issu du fichier

Pour un salaire net souhaité de 120 000 FCFA, le modèle estime notamment :

* salaire brut : environ 132 231 FCFA ;
* cotisation salariale : environ 11 901 FCFA ;
* IRPP : environ 330 FCFA ;
* charges patronales : environ 29 752 FCFA ;
* provision pour congés payés : environ 13 499 FCFA ;
* coût total employeur : environ 175 481 FCFA.

Ces résultats doivent uniquement servir à vérifier la cohérence de l’implémentation. Les taux et règles ne doivent pas être figés dans le code.

5. Calcul du brut à partir du net

Le calcul Net vers Brut doit utiliser une méthode itérative fiable.

Le système doit :

1. recevoir le net souhaité ;
2. estimer un premier brut ;
3. calculer les cotisations et l’IRPP ;
4. recalculer le brut nécessaire ;
5. répéter jusqu’à obtenir un net correspondant au montant demandé ;
6. gérer les arrondis selon les règles configurées ;
7. afficher l’écart résiduel éventuel.

La méthode doit fonctionner même lorsque :

* l’IRPP est progressif ;
* les personnes à charge modifient le calcul ;
* certaines primes sont exonérées ;
* certains avantages sont imposables ;
* les taux changent selon le pays ou le régime.

Le coût employeur doit inclure, selon les paramètres applicables :

* salaire brut ;
* cotisations patronales ;
* assurance ou mutuelle employeur ;
* retraite complémentaire ;
* provision pour congés payés ;
* primes employeur ;
* avantages en nature ;
* indemnités ;
* frais de recrutement ;
* équipements ;
* téléphone ;
* ordinateur ;
* véhicule ;
* formation ;
* autres charges directes ou indirectes.

Résultat principal

Afficher clairement :

Coût mensuel total du collaborateur

et

Coût annuel total du collaborateur

9. Connexion avec la Paie

Le simulateur doit être connecté au module Paie, sans modifier automatiquement une paie réelle tant que la simulation n’est pas validée.

Après validation, permettre de :

* créer une proposition salariale ;
* transférer les éléments vers la fiche du collaborateur ;
* préparer un avenant ;
* mettre à jour les éléments fixes de paie ;
* ajouter une prime ou un bonus ;
* appliquer une promotion ;
* générer le bulletin correspondant ;
* conserver l’historique de la décision.

Prévoir un workflow d’approbation avant toute application.

⸻

10. Connexion avec les avances sur salaire

Le simulateur doit prendre en compte les avances sur salaire déjà approuvées.

Afficher :

* avance reçue ;
* montant remboursé ;
* retenue du mois ;
* solde restant ;
* impact sur le net à payer.

Les avances ne doivent pas modifier le salaire brut contractuel. Elles doivent apparaître comme retenues distinctes sur le net à payer.

Dans :

Paramètres > Paie > Règles sociales et fiscales

permettre de configurer :

* cotisations salariales ;
* cotisations patronales ;
* tranches d’IRPP ;
* réductions pour personnes à charge ;
* plafonds ;
* éléments imposables ;
* éléments exonérés ;
* avantages en nature ;
* règles d’arrondi ;
* provisions pour congés ;
* devise ;
* date d’effet des taux ;
* historique des modifications.

Ne pas coder directement les taux dans les composants frontend.

* montant obtenu ;

Montant calculé : 11 901 FCFA

Charges patronales

Montant calculé : 29 752 FCFA

14. Avertissements et contrôles

Ajouter des alertes lorsque :

* le net demandé est supérieur au budget autorisé ;
* le coût employeur dépasse le plafond du poste ;
* une prime n’a pas de règle sociale définie ;
* un taux fiscal est manquant ;
* le salaire est inférieur au minimum configuré ;
* le salaire dépasse une grille salariale ;
* le résultat présente un écart de calcul ;
* une règle fiscale est expirée ;
* les paramètres du pays sont incomplets.

Le système ne doit jamais produire silencieusement un résultat potentiellement incorrect.

Résultat attendu

Je veux que le simulateur RH de Gameasu devienne un véritable outil d’aide à la décision permettant de répondre rapidement à des questions comme :

* Quel salaire brut faut-il proposer pour garantir un net précis ?
* Quel sera le net réel à partir d’un package brut ?
* Combien ce collaborateur coûtera-t-il réellement à l’organisation ?
* Quel sera l’impact d’une promotion ou d’un bonus ?
* Cette embauche est-elle compatible avec le budget et la trésorerie ?
* Quelles retenues et charges seront générées ?

Objectif final

Créer un simulateur salarial premium, bidirectionnel, transparent et connecté à tout l’écosystème Gameasu, capable de calculer avec précision le salaire net, le salaire brut et le coût total employeur, tout en s’adaptant aux règles sociales et fiscales de chaque pays.
