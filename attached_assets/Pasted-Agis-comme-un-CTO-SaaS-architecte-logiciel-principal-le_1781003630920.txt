==================================================
1. FONCTIONNEMENT GÉNÉRAL DU KIOSK
==================================================

Le kiosk de pointage doit permettre aux collaborateurs d’effectuer directement :

- **clock in / pointage à l’arrivée**
- **clock out / pointage au départ**
- **début de pause**
- **fin de pause / reprise**

### Logique attendue
Chaque action doit :
- être très simple à utiliser
- être clairement visible à l’écran
- être horodatée automatiquement
- être liée au bon collaborateur
- être synchronisée avec l’application principale
- être intégrée aux présences / pointages / rapports RH

==================================================
2. IDENTIFICATION PAR CODE UNIQUE À 4 CHIFFRES
==================================================

Chaque collaborateur doit avoir un **code unique à 4 chiffres**.

Ce code doit :
- être **unique**
- être assigné individuellement
- servir de **code de pointage kiosk**
- servir également de **Employee ID / identifiant employé**

### Logique attendue
Quand le collaborateur saisit son code à 4 chiffres dans le kiosk :
- le système doit retrouver automatiquement le collaborateur
- afficher son **nom**
- afficher si possible sa **photo**
- confirmer son identité visuellement
- lui permettre ensuite de choisir l’action :
  - arrivée
  - départ
  - début de pause
  - fin de pause / reprise

Prévoir aussi :
- validation du code
- message d’erreur si le code n’existe pas
- protection contre les doublons ou saisies incohérentes

==================================================
3. PHOTO OBLIGATOIRE À CHAQUE PUNCH
==================================================

Chaque pointage effectué depuis le kiosk doit automatiquement prendre une **photo**.

### À prévoir
Pour chaque punch :
- capture photo obligatoire
- lien de la photo avec le collaborateur
- lien de la photo avec le type de punch
- lien de la photo avec la date/heure
- lien de la photo avec l’organisation / tenant
- stockage consultable depuis l’application si nécessaire

### Objectif
Je veux pouvoir vérifier visuellement chaque pointage si besoin.

==================================================
4. TYPES DE PUNCH À GÉRER
==================================================

Le système doit au minimum gérer les types suivants :

- `clock_in`
- `clock_out`
- `break_start`
- `break_end`

### Logique métier
Le système doit empêcher ou signaler les cas incohérents, par exemple :
- clock out sans clock in préalable
- break start sans clock in
- break end sans break start
- double clock in sans clôture
- double break start
- punch dans un ordre non cohérent

Prévoir une logique de validation professionnelle et claire.

==================================================
5. SYNCHRONISATION DIRECTE AVEC L’APPLICATION PRINCIPALE
==================================================

Le kiosk ne doit pas fonctionner en silo.

Je veux que tous les punches effectués sur le kiosk soient **directement visibles dans l’application principale**.

### Exemple
Quand un collaborateur pointe sur le kiosk :
- le pointage doit apparaître dans **Présence & Pointage**
- le pointage doit apparaître dans l’historique du collaborateur
- la photo doit être liée au punch
- les rapports RH doivent intégrer ce punch
- les anomalies éventuelles doivent aussi être prises en compte

### Très important
La synchronisation doit être :
- immédiate ou quasi temps réel
- fiable
- cohérente
- multi-tenant aware

==================================================
6. DOUBLE MODE DE POINTAGE
==================================================

Le collaborateur doit pouvoir pointer de deux façons :

### Option 1
Depuis le **kiosk**

### Option 2
Depuis l’**application principale**

Les deux modes doivent :
- coexister proprement
- alimenter la même logique de présence
- remonter dans les mêmes historiques et rapports
- être cohérents entre eux

==================================================
7. LOGIQUE SAAS / MULTI-TENANT
==================================================

Comme il s’agit d’une plateforme SaaS, il faut que la logique soit **multi-tenant**.

### Attentes
- chaque organisation doit avoir son propre kiosk
- chaque organisation doit avoir ses propres collaborateurs
- les collaborateurs ne doivent pouvoir pointer que dans le kiosk de leur organisation
- les punches doivent être rattachés au bon tenant
- les paramètres du kiosk doivent être propres à chaque organisation
- le branding du kiosk peut être lié à chaque organisation si pertinent

Prévoir une architecture permettant :
- un kiosk par organisation
- plusieurs kiosks par organisation si nécessaire plus tard
- configuration indépendante par tenant
