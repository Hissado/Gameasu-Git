Pouvez-vous faire une revue complète, une évaluation et une correction de tous les rapports PDF générés par l’application Gameasu ?

Problème constaté

Les rapports sont souvent propres lorsqu’on les visualise dans l’application, mais dès qu’on les télécharge en PDF, le rendu n’est pas correct.

Exemple avec le rapport de gestion téléchargé :

* certains blocs débordent de la page ;
* certaines colonnes sont coupées ;
* certains tableaux ne sont pas bien ajustés ;
* les cartes KPI ne respectent pas toujours la largeur de la page ;
* certaines sections semblent trop larges pour le format PDF ;
* les alignements changent entre la visualisation web et le fichier PDF ;
* les pieds de page et numéros de page ne sont pas toujours bien positionnés ;
* certains contenus à droite sont partiellement invisibles ;
* les pages ne sont pas toujours bien équilibrées.

Le rendu visuel dans l’application est correct, mais le PDF final doit être aussi propre, aligné et professionnel.

⸻

Objectif

Je veux que tous les rapports PDF générés par Gameasu soient :

* propres ;
* bien alignés ;
* bien ajustés au format de page ;
* lisibles ;
* professionnels ;
* sans débordement ;
* sans colonnes coupées ;
* sans texte tronqué ;
* prêts à être partagés avec un client, un manager, une direction ou un partenaire.

Le PDF téléchargé doit correspondre fidèlement au rendu attendu, et ne pas casser la mise en page.

⸻

1. Auditer tous les rapports PDF de l’application

Merci d’identifier tous les rapports PDF générés dans Gameasu et de les tester un par un.

Rapports à vérifier au minimum :

* Rapport de gestion
* Rapport financier
* Rapport comptable
* Rapport analytique
* Rapport trésorerie
* Rapport ventes
* Rapport achats
* Rapport fournisseurs
* Rapport clients
* Rapport stock
* Rapport RH
* Rapport paie
* Rapport présences / kiosk
* Rapport projets
* Rapport opérations
* Rapport budget vs réalisé
* Rapport Cockpit
* Factures PDF
* Devis PDF
* Bons de commande PDF
* Reçus PDF

Chaque rapport doit être testé en mode visualisation et en mode téléchargement PDF.

⸻

2. Corriger les problèmes de débordement

Merci de corriger tous les éléments qui dépassent la largeur ou la hauteur de la page PDF.

À vérifier et corriger :

* tableaux trop larges ;
* cartes KPI trop grandes ;
* grilles mal dimensionnées ;
* colonnes coupées ;
* textes qui débordent ;
* montants trop longs ;
* badges et statuts coupés ;
* graphiques trop larges ;
* sections qui sortent de la page ;
* blocs à droite partiellement invisibles ;
* contenu masqué après export.

Aucun élément ne doit sortir du cadre de la page PDF.

⸻

3. Adapter les rapports au format PDF

Merci de revoir la logique de génération PDF pour garantir un rendu stable.

Prévoir :

* format A4 portrait par défaut ;
* format paysage pour les rapports avec grands tableaux si nécessaire ;
* marges internes suffisantes ;
* largeur maximale contrôlée ;
* contenu centré dans la page ;
* pagination propre ;
* séparation correcte entre les pages ;
* éviter les coupures au milieu des cartes ou tableaux ;
* gérer correctement les sauts de page ;
* utiliser page-break-inside: avoid ou équivalent sur les blocs importants ;
* réduire automatiquement certaines grilles en PDF ;
* adapter la taille des polices en mode PDF si nécessaire.

⸻

4. Créer un style spécial pour l’export PDF

Ne pas dépendre uniquement du style web affiché dans l’application.

Créer ou améliorer un style dédié aux PDF :

* print styles
* classes spécifiques PDF
* largeur fixe adaptée au format A4
* marges propres
* tailles de police adaptées
* tableaux optimisés
* cartes KPI redimensionnées
* graphiques ajustés
* pieds de page stables
* en-têtes cohérents

Le rendu web peut être différent du rendu PDF, mais le PDF doit rester professionnel et parfaitement ajusté.

⸻

5. Corriger les tableaux

Les tableaux sont souvent la cause principale des débordements.

Merci de revoir tous les tableaux dans les PDF :

* largeur des colonnes ;
* retour à la ligne automatique ;
* taille des montants ;
* alignement des nombres ;
* colonnes prioritaires ;
* colonnes optionnelles masquées en PDF si nécessaire ;
* version paysage si le tableau est trop large ;
* suppression du scroll horizontal dans le PDF ;
* adaptation des longues valeurs ;
* affichage propre des montants et pourcentages.

Si un tableau contient trop de colonnes, proposer une version PDF mieux structurée au lieu de simplement copier la vue web.

⸻

6. Corriger les cartes KPI et blocs de résumé

Merci de revoir les cartes KPI dans les rapports PDF.

Les cartes doivent :

* rester dans la largeur de la page ;
* être bien alignées ;
* avoir des tailles cohérentes ;
* ne pas déborder ;
* afficher correctement les montants longs ;
* passer sur plusieurs lignes si nécessaire ;
* garder une bonne lisibilité.

Exemples de montants à tester :

* 0 FCFA
* 91830000 FCFA
* 1 612 100 000 FCFA
* 71 050 000 FCFA
* 5 085 508 000 FCFA

⸻

7. Vérifier les en-têtes et pieds de page

Merci de corriger les headers et footers des PDF.

Vérifier :

* logo ;
* nom de l’organisation ;
* titre du rapport ;
* période ;
* date de génération ;
* mention confidentielle ;
* numéro de page ;
* pied de page ;
* alignement ;
* espace entre le contenu et le footer.

Le numéro de page doit être proprement affiché, par exemple :

Page 1 / 8

et non coupé, mal aligné ou réparti sur plusieurs lignes.

⸻

8. Vérifier la cohérence entre visualisation et PDF téléchargé

Le rapport affiché dans l’application peut être propre, mais le téléchargement PDF ne doit pas casser le design.

Merci de comparer :

1. rendu dans l’application ;
2. aperçu avant export ;
3. PDF téléchargé.

Le PDF final doit être validé visuellement.

Si nécessaire, créer un composant séparé pour le rendu PDF afin d’éviter les différences entre le DOM web et le rendu PDF.

⸻

9. Tester plusieurs tailles de données

Merci de tester les rapports avec différents volumes de données :

* peu de données ;
* données moyennes ;
* beaucoup de données ;
* montants très longs ;
* noms clients longs ;
* noms fournisseurs longs ;
* plusieurs pages ;
* tableaux avec beaucoup de lignes ;
* rapports avec sections vides ;
* rapports avec données manquantes.

Le PDF doit rester propre dans tous les cas.

⸻

10. Branding Gameasu

Les rapports PDF doivent garder une présentation professionnelle alignée avec Gameasu :

* couleurs cohérentes ;
* titres propres ;
* sections bien séparées ;
* tableaux lisibles ;
* cartes bien dimensionnées ;
* marges régulières ;
* typographie professionnelle ;
* aucun rendu cassé ;
* aucune surcharge visuelle.

Le rapport doit pouvoir être envoyé directement à un client ou à une direction.

⸻

11. Tests techniques à effectuer

Merci de tester :

* génération PDF en local ;
* génération PDF en production ;
* téléchargement PDF ;
* aperçu PDF ;
* rendu sur Chrome ;
* rendu sur Safari si possible ;
* rendu mobile si l’export est déclenché depuis mobile ;
* rapports avec plusieurs pages ;
* rapports avec grands tableaux ;
* rapports avec graphiques ;
* rapports avec données longues.

Vérifier aussi la console et corriger toute erreur liée à la génération PDF.

⸻

12. Résultat attendu

À la fin, merci de fournir :

* la liste des rapports PDF audités ;
* les problèmes identifiés ;
* les corrections appliquées ;
* les fichiers ou composants modifiés ;
* les styles PDF ajoutés ou corrigés ;
* les rapports testés ;
* les rapports encore à améliorer si nécessaire ;
* les recommandations pour éviter ces problèmes à l’avenir.

Objectif final

Tous les rapports PDF de Gameasu doivent être propres, lisibles, bien alignés, sans débordement, sans colonnes coupées et parfaitement adaptés au format PDF.

Le rendu PDF téléchargé doit être aussi professionnel que la visualisation dans l’application.
