Veuillez améliorer le module **Rapports / Reports** de l’application **Gaméasù** afin de rendre tous les rapports plus complets, exportables et exploitables.

### 1. Export Excel et PDF pour tous les rapports

Faire en sorte que **tous les rapports**, sans exception, puissent être exportés dans les formats suivants :

* Excel `.xlsx`
* PDF
* CSV, si possible
* Impression directe

Cette fonctionnalité doit être disponible pour :

* Les rapports standards
* Les rapports personnalisés
* Les rapports de gestion
* Les KPIs
* Les dashboards
* Les rapports budgétaires
* Les rapports prévisionnels
* Les rapports financiers
* Les rapports comptables
* Les rapports RH
* Les rapports opérationnels

Chaque rapport doit avoir des boutons visibles :

* **Exporter en Excel**
* **Exporter en PDF**
* **Imprimer**
* **Partager**

Les exports doivent garder une mise en forme professionnelle avec :

* Le nom de l’entreprise
* Le logo si disponible
* Le titre du rapport
* La période sélectionnée
* La date de génération
* Les filtres appliqués
* Les totaux et sous-totaux
* Les tableaux correctement alignés
* Une présentation propre et lisible

---

### 2. Amélioration du filtre de dates

Améliorer tous les filtres de dates dans les rapports, budgets, prévisions, dashboards et KPIs.

Ajouter une option **Date personnalisée / Custom Date** permettant à l’utilisateur de choisir librement :

* Une date de début
* Une date de fin

Le filtre de dates doit inclure les options suivantes :

* Aujourd’hui
* Cette semaine
* Ce mois
* Ce trimestre
* Cette année
* Mois dernier
* Trimestre dernier
* Année dernière
* Exercice fiscal en cours
* Exercice fiscal précédent
* Year-to-date
* Month-to-date
* Quarter-to-date
* **Date personnalisée**

Lorsque l’utilisateur choisit **Date personnalisée**, afficher deux champs :

* **Date de début**
* **Date de fin**

Le rapport doit automatiquement se recalculer selon la période choisie.

---

### 3. Gestion des exercices fiscaux sur plusieurs années

Actuellement, seuls les exercices liés à **2026** s’affichent dans certaines sections comme :

* Budget
* Gestion prévisionnelle
* Forecast
* Rapports financiers
* Rapports de gestion
* Comparaison budget vs réel
* Prévisions de trésorerie

Corriger cela afin que l’application prenne en charge plusieurs exercices fiscaux historiques et futurs.

L’utilisateur doit pouvoir sélectionner au minimum les exercices fiscaux suivants :

* 2015
* 2016
* 2017
* 2018
* 2019
* 2020
* 2021
* 2022
* 2023
* 2024
* 2025
* 2026
* 2027
* 2028
* 2029
* 2030

L’objectif est d’avoir au moins **10 années d’historique minimum**, ainsi que la possibilité d’ajouter les années futures.

---

### 4. Configuration dynamique des exercices fiscaux

Ne pas coder uniquement l’année 2026 en dur.

Créer une logique dynamique permettant de gérer les exercices fiscaux par entreprise / organisation.

Chaque entreprise doit pouvoir configurer :

* Son année fiscale
* Le mois de début de l’exercice fiscal
* Le mois de fin de l’exercice fiscal
* Les exercices ouverts
* Les exercices clôturés
* Les exercices archivés
* Les exercices prévisionnels futurs

Par exemple :

* Exercice fiscal janvier à décembre
* Exercice fiscal juillet à juin
* Exercice fiscal octobre à septembre

Cette configuration doit être respectée dans tous les modules concernés.

---

### 5. Application dans tous les modules

Appliquer cette amélioration partout où il y a des dates, des budgets, des prévisions ou des rapports, notamment :

* Finance
* Comptabilité
* Budget
* Gestion prévisionnelle
* Trésorerie
* Rapports
* KPIs
* Dashboards
* Projets
* Services
* RH
* Ventes
* Dépenses
* Clients
* Fournisseurs

Aucun module ne doit rester limité uniquement à 2026.

---

### 6. Comparaison entre périodes et exercices

Ajouter la possibilité de comparer les données entre plusieurs périodes ou exercices.

Exemples :

* 2026 vs 2025
* 2025 vs 2024
* Budget 2026 vs Réel 2026
* Réel 2025 vs Réel 2024
* Prévision 2027 vs Budget 2027
* Mois actuel vs mois précédent
* Trimestre actuel vs trimestre précédent
* Year-to-date actuel vs year-to-date précédent

Cette logique doit être disponible dans les rapports financiers, budgétaires, de gestion et les dashboards.

---

### 7. Exigence technique

Mettre en place une structure propre et scalable.

Prévoir notamment :

* Une table ou configuration des exercices fiscaux
* Une gestion dynamique des plages de dates
* Une logique multi-tenant avec `organization_id`
* Une API permettant de récupérer les exercices disponibles par organisation
* Une API permettant de générer les rapports selon les dates choisies
* Une API d’export Excel
* Une API d’export PDF
* Une API d’export CSV si possible
* Une logique d’autorisation selon les rôles utilisateurs

Ne pas utiliser de valeurs codées en dur comme uniquement `2026`.

Le système doit être flexible, professionnel, scalable et prêt pour une vraie utilisation en production.

---

### Résultat attendu

À la fin, l’utilisateur doit pouvoir :

1. Ouvrir n’importe quel rapport.
2. Choisir une période prédéfinie ou une date personnalisée.
3. Sélectionner un exercice fiscal parmi plusieurs années.
4. Comparer plusieurs périodes ou exercices.
5. Exporter le rapport en Excel ou PDF.
6. Utiliser ces fonctionnalités dans les budgets, prévisions, dashboards et rapports de gestion.

Le module doit fonctionner comme un vrai centre de reporting professionnel, flexible et complet, digne d’une application SaaS enterprise-grade.
