Revoir le comportement de la visite guidée du Plan comptable et des autres modules

Pouvez-vous revoir complètement le fonctionnement de la visite guidée (Onboarding / Product Tour) dans Gameasu, notamment dans le module Plan comptable, afin qu’elle soit beaucoup plus discrète, intuitive et non bloquante ?

Problème constaté

Actuellement, lorsque la visite guidée est affichée (comme sur la capture ci-jointe), elle occupe une très grande partie de l’écran avec un fond sombre qui masque presque toute l’application.

L’utilisateur ne peut pratiquement plus :

* consulter les informations du module ;
* naviguer dans les menus ;
* comprendre le contexte de ce qui est expliqué ;
* continuer à utiliser normalement l’application.

Cette approche donne une impression de blocage et nuit à l’expérience utilisateur.

⸻

Comportement attendu

La visite guidée doit accompagner l’utilisateur, et non bloquer son travail.

Je souhaite une expérience similaire à celle des meilleures applications SaaS (Notion, Slack, Stripe, HubSpot, QuickBooks, Microsoft 365, Odoo, etc.).

La visite doit être légère, élégante et laisser l’utilisateur libre de naviguer.

⸻

Réduire l’overlay

Le fond sombre ne doit pas masquer toute l’application.

Je recommande :

* un voile beaucoup plus léger (ou aucun voile) ;
* uniquement l’élément expliqué mis en évidence (spotlight) ;
* le reste de l’interface restant visible et compréhensible.

L’utilisateur doit toujours pouvoir situer l’élément présenté dans son contexte.

⸻

Revoir les fenêtres d’explication

Les fenêtres de la visite guidée doivent être :

* plus petites ;
* mieux positionnées ;
* adaptatives selon la taille de l’écran ;
* non intrusives ;
* élégantes et modernes.

Elles ne doivent jamais masquer :

* les menus ;
* les boutons principaux ;
* les tableaux ;
* les formulaires ;
* les actions importantes.

⸻

Mettre en évidence uniquement l’élément concerné

Lorsqu’une étape explique un composant, mettre uniquement ce composant en évidence.

Exemple :

Si l’étape concerne :

Plan comptable

Le système doit :

* entourer le menu ;
* ajouter une légère animation ;
* afficher une infobulle à proximité.

Le reste de l’application doit rester visible.

⸻

Navigation libre

Même lorsqu’une visite est en cours, l’utilisateur doit pouvoir :

* faire défiler la page ;
* consulter les informations affichées ;
* ouvrir un menu si nécessaire ;
* interrompre temporairement la visite ;
* reprendre plus tard.

La visite ne doit pas bloquer complètement l’interface.

⸻

Contrôler le comportement sur les grands tableaux

Dans des modules comme :

* Plan comptable ;
* Grand livre ;
* Journaux ;
* Collaborateurs ;
* Clients ;
* Fournisseurs ;

la visite ne doit jamais masquer les données du tableau.

L’utilisateur doit pouvoir voir les lignes tout en lisant les explications.

⸻

Adapter automatiquement le positionnement

Le système doit détecter l’emplacement de l’élément expliqué et placer automatiquement l’infobulle :

* à droite ;
* à gauche ;
* au-dessus ;
* en dessous ;

selon l’espace disponible.

Éviter que les fenêtres sortent de l’écran ou recouvrent les éléments importants.

⸻

Vérifier toute l’application

Merci de parcourir tous les modules utilisant une visite guidée :

* Tableau de bord ;
* Ventes ;
* CRM ;
* Achats ;
* Comptabilité ;
* Plan comptable ;
* Trésorerie ;
* Fiscalité ;
* Ressources Humaines ;
* Paie ;
* Projets ;
* Logistique ;
* Administration ;
* Paramètres ;
* Cockpit ;
* Portail Expert.

La logique de la visite guidée doit être identique partout.

⸻

Expérience utilisateur

L’utilisateur doit toujours avoir accès aux actions suivantes :

* Suivant
* Précédent
* Ignorer
* Terminer
* Reprendre plus tard

Prévoir également une option :

Ne plus afficher cette visite

Cette préférence doit être enregistrée par utilisateur, par organisation et par module.

⸻

Responsive

La visite guidée doit fonctionner parfaitement sur :

* ordinateur ;
* tablette ;
* smartphone.

Les fenêtres doivent se repositionner automatiquement sans masquer les boutons essentiels.

⸻

Résultat attendu

Je souhaite une visite guidée moderne, élégante et non bloquante, qui aide réellement l’utilisateur à découvrir les fonctionnalités de Gameasu tout en lui laissant le contrôle de l’application.

Objectif final

Transformer les visites guidées de Gameasu en un véritable assistant d’apprentissage interactif, inspiré des meilleures plateformes SaaS, où l’utilisateur peut apprendre progressivement sans que l’interface soit masquée ou que sa navigation soit interrompue.
