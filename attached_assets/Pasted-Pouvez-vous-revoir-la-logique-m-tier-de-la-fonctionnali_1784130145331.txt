Pouvez-vous revoir la logique métier de la fonctionnalité Avances sur salaire afin qu’elle reflète un processus RH réaliste, conforme aux bonnes pratiques des ERP professionnels ?

Objectif

L’expérience doit être adaptée au rôle de chaque utilisateur. Un collaborateur ne doit pas gérer les paramètres ou les politiques de l’entreprise ; il doit uniquement pouvoir effectuer une demande. Toutes les règles et validations doivent être gérées par les responsables autorisés.

⸻

1. Parcours du collaborateur

L’accès aux Avances sur salaire ne doit pas se trouver dans le menu principal RH.

Le collaborateur doit y accéder depuis :

Mon espace → Mes avances sur salaire

Depuis cette section, il doit pouvoir :

* consulter ses avances en cours ;
* consulter son historique ;
* effectuer une nouvelle demande d’avance ;
* choisir le montant demandé ;
* proposer un mode de remboursement (sur un mois ou plusieurs mois, selon la politique de l’entreprise) ;
* joindre un justificatif si nécessaire ;
* suivre le statut de sa demande ;
* recevoir des notifications à chaque étape du traitement.

Le collaborateur ne doit pas pouvoir modifier les politiques ou approuver une demande.

⸻

2. Workflow de validation

Une fois la demande soumise, un workflow d’approbation doit être déclenché automatiquement.

Selon la configuration de l’organisation, la demande peut être envoyée :

* au superviseur direct ;
* au responsable RH ;
* au gestionnaire de la paie ;
* ou à un approbateur défini dans le workflow.

Chaque approbateur doit pouvoir :

* consulter la demande ;
* analyser les informations ;
* approuver ;
* rejeter ;
* demander des informations complémentaires ;
* ajouter un commentaire.

Toutes les actions doivent être historisées.

⸻

3. Intégration avec la paie

Lorsqu’une demande est approuvée :

* l’avance est enregistrée automatiquement ;
* le calendrier de remboursement est généré ;
* les retenues sont intégrées automatiquement dans la paie selon les règles définies ;
* le solde restant dû est mis à jour après chaque traitement de paie.

⸻

4. Gestion des politiques (Administrateur)

La gestion des politiques d’avances sur salaire doit être réservée aux utilisateurs autorisés.

Par exemple :

Équipe → Paramètres RH → Politiques d’avances sur salaire

Seuls les administrateurs RH ou les personnes autorisées doivent pouvoir :

* créer une politique ;
* modifier une politique ;
* supprimer une politique ;
* définir les conditions d’éligibilité ;
* fixer le montant maximum autorisé ;
* définir le nombre maximal d’avances par an ;
* définir les modalités de remboursement ;
* configurer les workflows d’approbation ;
* définir les rôles autorisés à approuver.

⸻

5. Même logique pour les politiques de congés

Le même principe doit s’appliquer aux politiques de congés.

L’administrateur est le seul habilité à :

* créer ;
* modifier ;
* supprimer les politiques de congés ;
* définir les règles d’acquisition ;
* configurer les types de congés ;
* définir les workflows de validation.

Les collaborateurs, quant à eux, doivent uniquement pouvoir :

* consulter leur solde ;
* soumettre une demande de congé ;
* suivre son traitement ;
* consulter leur historique.

⸻

6. Résultat attendu

Je souhaite que la gestion des avances sur salaire et des politiques RH respecte une séparation claire des responsabilités :

* Le collaborateur effectue ses demandes depuis Mon espace.
* Le superviseur, le RH ou le gestionnaire de paie les analysent et les approuvent selon le workflow défini.
* L’administrateur configure et gère les politiques, les paramètres et les règles applicables.

Objectif final

Mettre en place un processus RH réaliste, sécurisé et conforme aux meilleures pratiques des ERP modernes, où chaque utilisateur accède uniquement aux fonctionnalités correspondant à son rôle, tout en garantissant une automatisation complète des validations et de l’intégration avec la paie.
