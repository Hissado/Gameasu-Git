Pouvez-vous ajouter dans Gameasu une **courte description pédagogique pour chaque module, sous-module et section de navigation**, afin que les utilisateurs comprennent immédiatement le rôle de chaque fonctionnalité ?

## Objectif

Gameasu est un ERP riche qui peut être utilisé par des personnes ayant différents niveaux d’expérience.

Je veux que chaque utilisateur puisse comprendre facilement :

* à quoi sert un module ;
* quelles opérations il peut y réaliser ;
* quelles informations il peut y consulter ;
* dans quel contexte utiliser chaque sous-section.

Les descriptions doivent être simples, courtes, professionnelles et orientées vers l’action.

---

### Achats

**Gérez vos fournisseurs, demandes d’achat, commandes, dépenses, factures et paiements.**

### Équipe

**Gérez vos collaborateurs, contrats, congés, présences, paie, recrutements et réclamations.**

**Configurez votre organisation, vos utilisateurs, permissions, abonnements, modules et paramètres.**

# 4. Comportement attendu dans le menu latéral

Le menu de la capture étant compact, les descriptions ne doivent pas surcharger visuellement la navigation.

## Lorsque le menu est développé

Afficher :

* le nom du module ;
* une courte description sur une deuxième ligne ;
* un texte plus petit et plus discret ;
* une largeur et un espacement adaptés.

Exemple :

**Finance**
*Trésorerie, budgets et comptabilité*

## Lorsque le menu est réduit

Afficher la description dans une infobulle au survol de l’icône.

## Sur mobile et tablette

Comme le survol n’existe pas :

* afficher une icône d’information si nécessaire ;
* ouvrir une infobulle ou un petit popover au toucher ;
* permettre de fermer facilement l’explication.

---

# 5. Afficher les descriptions à plusieurs endroits

Les descriptions doivent être disponibles :

* dans le menu principal ;
* dans les sous-menus ;
* sur les cartes de modules ;
* sur la page d’accueil de chaque module ;
* dans les états vides ;
* dans la recherche globale ;
* dans les raccourcis du tableau de bord ;
* dans la visite guidée ;
* dans l’ERP ;
* dans le Cockpit ;
* dans le portail expert.

Sur les pages d’accueil des modules, la description peut être légèrement plus détaillée que dans le menu latéral.

# 6. Ajouter des descriptions aux onglets et actions importantes

Chaque onglet ou bouton dont la fonction peut être ambiguë doit aussi comporter une explication.

### Informations générales

**Consultez ou modifiez les principales informations de cette fiche.**

### Documents

**Ajoutez et consultez les fichiers liés à cet enregistrement.**

### Historique

**Retrouvez toutes les actions et modifications effectuées.**

### Archiver

**Retire cet élément des listes actives sans supprimer ses données.**

### Soumettre pour validation

**Transmet cette demande à la personne autorisée à l’approuver.**

---

# 7. Centraliser toutes les descriptions

Ne pas ajouter les textes séparément dans chaque composant.

Créer un dictionnaire ou une configuration centralisée contenant :

* identifiant du module ;
* libellé officiel ;
* description courte pour le menu ;
* description détaillée pour la page du module ;
* route ;
* icône ;
* module parent ;
* ordre d’affichage ;
* traduction éventuelle.

Toute modification apportée au dictionnaire doit se mettre à jour automatiquement partout dans l’application.

---

# 8. Respecter les modules actifs et les permissions

Les descriptions affichées doivent correspondre :

* au pack de l’organisation ;
* aux modules actifs ;
* au rôle de l’utilisateur ;
* à ses permissions ;
* à l’organisation actuellement sélectionnée.

Ne pas présenter une action comme disponible lorsque l’utilisateur n’a pas l’autorisation de l’utiliser.

Lorsqu’une fonctionnalité est verrouillée, expliquer clairement pourquoi :

* non incluse dans la formule ;
* désactivée par l’administrateur ;
* permission insuffisante ;
* add-on non activé.

---

# 9. Qualité rédactionnelle

Toutes les descriptions doivent être :

* entièrement en français ;
* courtes ;
* claires ;
* pédagogiques ;
* cohérentes ;
* adaptées aux non-spécialistes ;
* alignées avec les fonctionnalités réelles de Gameasu.

Éviter :

* le jargon technique ;
* les clés internes comme `finance.read` ;
* les phrases longues ;
* les termes anglais inutiles ;
* les descriptions vagues qui ne précisent pas l’action réalisable.

---

# 10. Résultat attendu

Je veux que chaque module, sous-module, onglet et action importante de Gameasu possède une description claire.

L’utilisateur doit pouvoir comprendre immédiatement :

* où il se trouve ;
* à quoi sert la section ;
* ce qu’il peut y faire ;
* quelle est la prochaine action recommandée.

### Objectif final

Faire de Gameasu un ERP premium, intuitif et auto-explicatif, accessible aussi bien aux utilisateurs débutants qu’aux experts, sans surcharger visuellement le menu latéral ni compliquer la navigation.
