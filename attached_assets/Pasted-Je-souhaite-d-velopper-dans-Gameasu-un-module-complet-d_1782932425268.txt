Je souhaite développer dans Gameasu un module complet de **pointage, paie, congés payés et export Excel professionnel**, basé sur les rapports et documents joints.

L’objectif est d’analyser les fichiers fournis, notamment le modèle Excel **“Pointage Modèle”**, afin de reproduire dans l’ERP la même logique de calcul, la même structure de données et le même format d’export.

Le module doit permettre d’automatiser tout le processus lié au suivi du personnel, au calcul des heures travaillées, aux absences, aux congés payés, aux retards, aux heures supplémentaires et à la préparation de la paie.

### 1. Analyse des documents joints

Veuillez analyser tous les fichiers fournis afin d’identifier :

* la structure du rapport de pointage ;
* les colonnes utilisées ;
* les formules de calcul ;
* les règles appliquées pour les heures normales ;
* les règles appliquées pour les heures supplémentaires ;
* les règles de calcul des absences ;
* les règles de calcul des congés payés ;
* les totaux par employé ;
* les totaux par période ;
* les informations nécessaires pour préparer la paie ;
* la mise en page exacte du fichier Excel exporté.

Le but est de comprendre précisément comment le fichier **Pointage Modèle** fonctionne afin de le reproduire automatiquement dans Gameasu.

### 2. Fonctionnalités attendues dans l’ERP

Créer un module permettant de gérer :

* les employés ;
* les contrats ;
* les postes ;
* les départements ;
* les horaires de travail ;
* les jours ouvrables ;
* les jours fériés ;
* les pointages journaliers ;
* les heures d’arrivée et de départ ;
* les pauses ;
* les retards ;
* les absences ;
* les permissions ;
* les congés payés ;
* les congés non payés ;
* les heures normales ;
* les heures supplémentaires ;
* les avances sur salaire ;
* les primes ;
* les retenues ;
* le salaire brut ;
* le salaire net ;
* les éléments variables de paie.

### 3. Logique de calcul à automatiser

Le système doit automatiquement calculer :

* le nombre de jours travaillés ;
* le nombre d’heures travaillées ;
* les heures normales ;
* les heures supplémentaires ;
* les jours d’absence ;
* les jours de congés payés ;
* les jours de congés non payés ;
* les retards ;
* les retenues liées aux absences ou retards ;
* les indemnités ou primes éventuelles ;
* le total à payer par employé ;
* le récapitulatif global de la période.

Toutes les formules doivent être dynamiques, paramétrables et non codées en dur.

### 4. Paramétrage nécessaire

Ajouter une page de configuration permettant à l’administrateur de définir :

* la durée normale de travail par jour ;
* la durée normale de travail par semaine ;
* les jours travaillés dans la semaine ;
* les règles de calcul des heures supplémentaires ;
* le taux de majoration des heures supplémentaires ;
* les règles de calcul des congés payés ;
* le nombre de jours de congés acquis par mois ;
* les règles de retenue pour absence ;
* les règles de retenue pour retard ;
* les jours fériés ;
* les périodes de paie ;
* les devises ;
* les règles propres à chaque entreprise ou tenant.

Chaque entreprise cliente doit pouvoir avoir ses propres paramètres.

### 5. Gestion multi-tenant

Le module doit respecter l’architecture multi-tenant de Gameasu.

Chaque tenant ou entreprise cliente doit avoir :

* ses propres employés ;
* ses propres règles de pointage ;
* ses propres règles de paie ;
* ses propres périodes de paie ;
* ses propres rapports ;
* ses propres exports Excel.

Les données d’un tenant ne doivent jamais être visibles par un autre tenant.

### 6. Interface utilisateur

Créer une interface claire et professionnelle avec les pages suivantes :

* Tableau de bord RH & Paie ;
* Liste des employés ;
* Fiche employé ;
* Pointage journalier ;
* Import des pointages ;
* Validation des pointages ;
* Gestion des absences ;
* Gestion des congés payés ;
* Configuration des règles de paie ;
* Préparation de la paie ;
* Rapport de pointage ;
* Rapport de paie ;
* Export Excel ;
* Historique des exports.

L’interface doit être simple, fluide, responsive et adaptée à une utilisation réelle par les entreprises.

### 7. Export Excel identique au modèle fourni

Le point le plus important est l’export Excel.

Quand l’utilisateur clique sur **Exporter**, Gameasu doit générer un fichier Excel qui reproduit le plus fidèlement possible le fichier **Pointage Modèle** fourni.

L’export doit inclure :

* le nom de l’entreprise ;
* la période concernée ;
* la liste des employés ;
* les jours de la période ;
* les heures ou jours pointés ;
* les absences ;
* les congés payés ;
* les congés non payés ;
* les heures supplémentaires ;
* les totaux par employé ;
* les totaux globaux ;
* les formules Excel dynamiques ;
* la même structure que le modèle ;
* une mise en page professionnelle prête à être imprimée ou partagée.

Le fichier Excel exporté ne doit pas être un simple tableau brut. Il doit être bien formaté, professionnel, lisible, avec titres, bordures, totaux, formules et mise en page similaire au modèle joint.

### 8. Import Excel

Prévoir aussi la possibilité d’importer un fichier Excel de pointage.

Le système doit pouvoir :

* lire les données importées ;
* détecter les employés ;
* reconnaître les dates ;
* récupérer les heures, absences et congés ;
* signaler les erreurs ;
* éviter les doublons ;
* permettre une validation avant enregistrement.

### 9. Base de données recommandée

Créer ou adapter les tables suivantes :

* employees
* departments
* job_positions
* employee_contracts
* attendance_records
* attendance_periods
* payroll_periods
* leave_requests
* leave_balances
* leave_types
* holidays
* payroll_settings
* overtime_rules
* payroll_calculations
* payroll_items
* payroll_exports
* import_logs
* audit_logs

Chaque table doit inclure un `organization_id` afin de respecter l’architecture multi-tenant.

### 10. Sécurité et validation

Mettre en place :

* contrôle des rôles et permissions ;
* validation des pointages avant paie ;
* verrouillage d’une période après validation ;
* historique des modifications ;
* audit log complet ;
* possibilité de corriger une période avec justification ;
* protection contre les erreurs de calcul ;
* vérification des doublons ;
* contrôle des données manquantes.

### 11. Résultat attendu

À la fin du développement, Gameasu doit être capable de :

* gérer les employés ;
* suivre le pointage ;
* calculer automatiquement les absences, congés payés, heures normales et heures supplémentaires ;
* préparer les éléments de paie ;
* permettre la validation par l’administrateur ;
* générer un rapport Excel identique ou très proche du fichier **Pointage Modèle** fourni ;
* permettre à chaque tenant d’avoir ses propres règles de calcul ;
* produire un rapport clair, fiable, professionnel et prêt à être utilisé pour la paie.

L’objectif final est de transformer le fichier Excel manuel actuel en un module ERP automatisé, fiable, paramétrable et exportable, tout en conservant le même rendu professionnel que le modèle existant.
