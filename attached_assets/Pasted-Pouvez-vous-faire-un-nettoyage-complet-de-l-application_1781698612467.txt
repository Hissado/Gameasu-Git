Pouvez-vous faire un nettoyage complet de l’application Gaméasù avant la publication officielle ?

Objectif

Je veux supprimer toutes les données existantes afin d’avoir une application totalement propre, sans aucun compte demo, sans ancien compte réel, sans données de test, sans ancienne organisation, sans utilisateur inutile et sans aucune trace des anciennes données.

L’application doit repartir sur une base propre, prête pour une vraie mise en production.

⸻

1. Supprimer toutes les données existantes

Merci de supprimer complètement :

* comptes demo
* comptes réels existants
* utilisateurs
* organisations / tenants
* invitations
* rôles assignés aux anciens utilisateurs
* permissions personnalisées
* abonnements
* paiements
* factures
* reçus
* tickets support
* incidents
* logs liés aux anciennes données
* données CRM
* clients
* prospects
* devis
* commandes
* factures clients
* encaissements
* données RH
* collaborateurs
* pointages
* paie
* congés
* données finance
* comptabilité
* trésorerie
* budgets
* rapports
* stock
* équipements
* locations
* documents
* données kiosk
* mock data
* seed data visible
* toute ancienne donnée liée à EDOLE ou edole.africa

⸻

2. Nettoyer la base de données sans casser l’application

Attention : je veux supprimer les données, mais ne pas casser la structure de l’application.

Merci de conserver :

* les tables
* les migrations
* les schémas
* les relations nécessaires
* les routes backend
* les composants frontend
* les paramètres techniques nécessaires
* la configuration du branding Gaméasù
* la configuration des domaines
* les variables d’environnement nécessaires

Le but est d’avoir une application vide mais fonctionnelle.

⸻

3. Supprimer les anciennes traces

Merci de vérifier qu’il ne reste aucune trace de :

* anciens tenants
* anciens utilisateurs
* anciens emails
* anciennes organisations
* anciennes données demo
* anciennes données EDOLE
* anciennes références edole.africa
* anciennes factures ou paiements
* anciens fichiers uploadés liés aux données demo
* anciens logs non nécessaires

L’application doit être propre comme si elle venait d’être installée pour la première fois.

⸻

4. Prévoir une base propre pour la production

Après nettoyage, l’application doit afficher des états vides propres, par exemple :

* Aucun client pour le moment
* Aucune facture créée
* Aucun utilisateur ajouté
* Aucun paiement enregistré
* Aucun ticket support
* Aucune organisation créée
* Aucun rapport disponible

Les pages ne doivent pas afficher d’erreur parce que les données sont vides.

⸻

5. Gestion du Super Admin

Comme tous les comptes doivent être supprimés, merci de prévoir une méthode sécurisée pour recréer le premier accès Super Admin après nettoyage.

Option recommandée :

* supprimer tous les anciens comptes
* créer un workflow de première configuration
* permettre de créer le premier Super Admin via un lien sécurisé
* ou créer uniquement le compte Super Admin officiel après nettoyage, si nécessaire

Le compte Super Admin officiel doit être recréé proprement, sans ancienne donnée attachée.

⸻

6. Sécurité avant suppression

Avant d’exécuter le nettoyage, merci de :

* confirmer l’environnement concerné : production, staging ou développement
* faire une sauvegarde complète si nécessaire
* éviter de supprimer les configurations techniques critiques
* documenter les tables nettoyées
* vérifier que l’application démarre correctement après nettoyage

⸻

7. Vérification après nettoyage

Après suppression, merci de tester :

* connexion
* création d’un nouveau tenant
* création d’un nouveau Super Admin
* invitation d’un utilisateur
* accès au Cockpit
* accès à l’application tenant
* génération d’un lien kiosk
* navigation dans tous les modules
* affichage des états vides
* absence d’erreurs frontend/backend
* absence d’anciennes données

⸻

8. Résultat attendu

Je veux une application Gaméasù complètement propre :

* aucun compte demo
* aucun ancien compte réel
* aucun ancien tenant
* aucune ancienne donnée
* aucune trace EDOLE
* aucune trace edole.africa
* aucun mock data visible
* aucune donnée incohérente
* aucune erreur liée aux données supprimées

Objectif final

Avoir une application vide, propre, sécurisée et prête pour la production, avec uniquement la structure nécessaire pour créer de vrais tenants, vrais utilisateurs et vraies données à partir de zéro.
