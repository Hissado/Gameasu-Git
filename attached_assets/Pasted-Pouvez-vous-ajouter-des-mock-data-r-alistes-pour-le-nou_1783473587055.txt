Pouvez-vous ajouter des mock data réalistes pour le nouveau module Contrôle fiscal préalable / Vérification des déclarations fiscales afin de permettre une vraie expérience de démonstration dans Gameasu ?

Objectif

Je veux que ce module ne soit pas vide lors des tests ou des démonstrations.
Il doit contenir des données réalistes permettant de comprendre concrètement comment une entreprise peut préparer, vérifier, corriger et valider ses déclarations fiscales avant soumission.

Les mock data doivent être disponibles pour le tenant :

Hissado Consulting

Et cela doit être le cas :

* en environnement de développement ;
* en environnement de production après publication.

2. Créer plusieurs scénarios réalistes

Ajouter plusieurs cas de test pour simuler une vraie utilisation du module.

Scénario 1 — Déclaration conforme

Créer une déclaration fiscale avec :

* ventes cohérentes ;
* TVA correctement calculée ;
* factures disponibles ;
* pièces justificatives complètes ;
* aucun écart majeur ;
* score de conformité élevé.

Statut attendu :

Prêt à soumettre

⸻

Scénario 2 — TVA collectée incohérente

Créer une déclaration où :

* le chiffre d’affaires comptable ne correspond pas au chiffre d’affaires déclaré ;
* la TVA collectée est inférieure à ce qui devrait être déclaré ;
* certaines factures clients ne sont pas prises en compte.

Anomalie attendue :

Risque élevé — TVA collectée incohérente avec les ventes enregistrées.

Action recommandée :

Vérifier les factures clients de la période et recalculer la TVA collectée.

⸻

Scénario 3 — TVA déductible sans justificatif

Créer une déclaration où certaines dépenses ou factures fournisseurs n’ont pas de justificatif attaché.

Anomalie attendue :

Risque moyen — TVA déductible sans pièce justificative.

Action recommandée :

Ajouter le justificatif fournisseur ou exclure la TVA déductible concernée.

⸻

Scénario 4 — Facture fournisseur incomplète

Créer une facture fournisseur avec :

* numéro fiscal manquant ;
* date incorrecte ;
* montant incohérent ;
* pièce jointe illisible ou absente.

Anomalie attendue :

Point non conforme — facture fournisseur incomplète.

⸻

Scénario 5 — Déclaration avec erreur bloquante

Créer une déclaration avec une erreur importante empêchant la soumission :

* période fiscale manquante ;
* montant déclaré différent du total comptable ;
* absence de pièces critiques ;
* taxe mal calculée.

Statut attendu :

Corrections requises

ou

Bloquant — déclaration non prête à soumettre

⸻

Scénario 6 — Déclaration corrigée

Créer un cas où une déclaration contient d’abord des anomalies, puis une correction est appliquée.

Afficher :

* anomalie initiale ;
* correction effectuée ;
* utilisateur ayant corrigé ;
* date de correction ;
* nouveau score de conformité ;
* statut final.

6. Vérifier le réalisme du module

Merci de revoir aussi les scénarios et fonctionnalités du module pour vérifier qu’ils sont réalistes, utiles et cohérents avec une vraie utilisation comptable et fiscale.

Points à vérifier

* Est-ce que les statuts sont cohérents ?
* Est-ce que les contrôles proposés sont réalistes ?
* Est-ce que les anomalies détectées sont crédibles ?
* Est-ce que le workflow de correction est logique ?
* Est-ce que le score de conformité est compréhensible ?
* Est-ce que les rapports générés sont utiles ?
* Est-ce que les permissions sont adaptées ?
* Est-ce que le module est bien connecté aux factures, ventes, achats, comptabilité, documents et rapports ?
* Est-ce que les règles fiscales sont configurables par pays ?
* Est-ce que l’interface est simple pour un comptable ou un dirigeant ?
