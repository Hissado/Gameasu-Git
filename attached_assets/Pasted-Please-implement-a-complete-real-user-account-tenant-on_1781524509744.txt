Please implement a complete real user account, tenant onboarding, secure invitation and authentication system for Gaméasù.

Objective

Now that the application is almost ready, I want to move from demo/mock access to real user accounts with secure onboarding, tenant invitation links, email invitations, temporary passwords, forced password reset, and email-based two-factor authentication.

The official domain is:

* Main domain: gameasu.tech
* Cockpit Platform: cockpit.gameasu.tech
* Sender email: noreply@gameasu.tech

⸻

1. Secure tenant onboarding from Cockpit Platform

The Super Admin must be able to generate a unique and secure onboarding link from the Cockpit Platform for each tenant / organization.

This link will allow a tenant organization to access the Gaméasù application and complete its onboarding.

Requirements

From cockpit.gameasu.tech, the Super Admin should be able to:

* create a new organization / tenant
* assign an organization admin
* generate a secure one-time onboarding link
* set link expiration date
* revoke or regenerate the link
* track whether the link was used
* see onboarding status
* send the link by email
* manually copy the link if needed

Security

The onboarding link must be:

* unique
* encrypted or signed
* tenant-specific
* one-time use if possible
* time-limited
* revocable
* protected against reuse
* tracked in audit logs

⸻

2. Organization admin user creation

Once the organization account is created, the assigned organization admin should receive an email invitation.

The admin should be able to:

* open the secure onboarding link
* sign up
* verify email
* receive or use a temporary password / one-time setup token
* be forced to create a new password
* activate the tenant account
* access the tenant workspace

Once activated, the tenant status should change to Actif.

⸻

3. User invitation by organization admin

After the organization is active, the organization admin must be able to invite users from inside the tenant app.

The admin should be able to:

* add a user
* enter user name and email
* assign role
* assign permissions
* assign modules or additional features
* send invitation email
* resend invitation
* revoke invitation
* see invitation status

Invitation statuses:

* En attente
* Envoyée
* Acceptée
* Expirée
* Révoquée

⸻

4. User sign-up flow

When a user receives an invitation email:

1. The user clicks the secure invitation link.
2. The system validates the invitation token.
3. The user lands on the sign-up page.
4. The user confirms their information.
5. A temporary password or secure setup token is assigned.
6. The system forces the user to create a new password.
7. The user completes email verification.
8. The account becomes active.
9. The organization admin receives a confirmation email.

Important

Users should never be able to access the platform unless:

* they were invited
* their invitation is valid
* their email is verified
* they created their own password
* their account is active
* their organization is active

⸻

5. Temporary password and forced password reset

If the system generates a temporary password:

* the temporary password should be valid for a limited time
* it must be securely hashed
* it must never be stored in plain text
* the user must be forced to change it at first login
* the user cannot access the app until a new password is created

A better secure option is to use a one-time password setup link instead of sending a plain temporary password.

⸻

6. Email-based Two-Factor Authentication

Please add two-factor authentication by email.

At each login:

* user enters email and password
* system sends a verification code to the user’s email
* user enters the code
* system validates the code
* access is granted only if the code is correct

Remember this computer

Add an option:

Remember this computer for 60 days

If selected:

* the user should not be asked for an email 2FA code again on the same trusted device for 60 days
* the trusted device should be stored securely
* the user should be able to revoke trusted devices later
* the system should still require 2FA if a new device, browser or suspicious login is detected

⸻

12. Kiosk link generation

The Kiosk link must not be generated from the Cockpit Platform.

The organization admin should generate the tenant-specific kiosk link from inside the organization app.

Kiosk link requirements

The organization admin should be able to:

* generate a unique kiosk link
* regenerate the kiosk link
* revoke the kiosk link
* display it as a QR code
* copy the kiosk URL
* assign it to a location, office, site or department
* track kiosk usage
* protect it from unauthorized use

Each tenant must have its own kiosk link and the kiosk must only allow clock-in / clock-out for users belonging to that tenant.
