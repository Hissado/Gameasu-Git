Pouvez-vous revoir la page d’enregistrement / inscription ERP afin qu’elle soit cohérente avec la logique du site web, du simulateur de prix, du paiement et de la page login ?

Problèmes constatés

Actuellement, plusieurs éléments ne suivent pas la logique attendue :

* la page d’enregistrement ne reprend pas exactement le design, les couleurs et le logo de la page login ;
* le texte “Aucune carte bancaire requise pour s’inscrire” n’est pas cohérent, car le client doit payer pour activer son accès à l’ERP ;
* la page affiche encore une étape du type “Suivant : choisir ma formule”, alors que le client a déjà choisi sa formule, le nombre d’utilisateurs et la périodicité dans le simulateur de prix du site web ;
* le parcours ne semble pas encore bien gérer le cas où un même email peut accéder à plusieurs organisations.

⸻

1. Harmoniser le design avec la page login

La page d’enregistrement doit utiliser le même univers visuel que la page login :

* même logo Gameasu ;
* mêmes couleurs ;
* même typographie ;
* même style de carte ;
* même fond ;
* mêmes boutons ;
* même niveau de finition premium ;
* même cohérence responsive mobile et desktop.

L’objectif est que l’utilisateur ait l’impression d’être dans le même produit, sans rupture visuelle entre login, inscription et paiement.

⸻

2. Supprimer le message “Aucune carte bancaire requise”

Merci de supprimer ou remplacer le message :

Aucune carte bancaire requise pour s’inscrire

Ce message n’est pas adapté à notre logique, car l’inscription doit mener au paiement avant activation complète de l’ERP.

Le client peut créer son compte, mais son accès aux modules doit être activé seulement après paiement validé.

Texte recommandé

Remplacer par :

Paiement requis pour activer votre espace ERP.

ou

Votre espace sera activé après validation du paiement.

ou

Créez votre compte, finalisez le paiement, puis accédez à vos modules Gameasu.

Important : ne pas dire que la carte bancaire est obligatoire, car plusieurs moyens de paiement peuvent être proposés :

* carte bancaire ;
* Mobile Money ;
* virement bancaire ;
* chèque ;
* dépôt en espèces sur compte ;
* dépôt en espèces au bureau.

⸻

3. Supprimer l’étape “Choisir ma formule”

Merci de retirer toute étape qui demande encore au client de choisir sa formule après son arrivée sur la page ERP.

La logique attendue est la suivante :

1. le client choisit déjà sa formule sur le site web ;
2. il choisit le nombre d’utilisateurs ;
3. il choisit la périodicité ;
4. il clique sur le CTA correspondant ;
5. il arrive sur la page d’inscription ERP avec ces informations déjà préremplies.

Donc il ne faut plus afficher :

Suivant : choisir ma formule

La prochaine étape doit plutôt être :

Suivant : finaliser le paiement

ou

Continuer vers le paiement

⸻

4. Préremplir automatiquement la formule choisie

La page d’inscription doit lire automatiquement les paramètres transmis depuis le site web.

Exemple d’URL

/erp/billing?plan=business&users=10&period=monthly

La page doit automatiquement afficher :

* Formule : Business
* Nombre d’utilisateurs : 10
* Périodicité : mensuelle
* Prix par utilisateur
* Montant total HT / TVA / TTC
* Devise
* Code promo ou partenaire si présent

Le client ne doit pas avoir à refaire son choix.

⸻

5. Afficher un résumé clair de l’abonnement

Sur la page d’inscription, afficher une carte récapitulative :

Votre sélection

* Formule choisie : Business
* Nombre d’utilisateurs : 10
* Périodicité : Mensuelle
* Prix par utilisateur : 7 000 FCFA TTC
* Total à payer : 70 000 FCFA TTC
* Prochaine étape : Paiement

Ajouter un lien discret :

Modifier ma sélection

Ce lien peut ramener vers la page tarifs du site web ou ouvrir le simulateur, mais par défaut la sélection doit être automatique.

⸻

6. Logique d’inscription

Le client doit renseigner uniquement les informations nécessaires à la création de son espace ERP :

* nom complet ;
* email professionnel ;
* téléphone ;
* nom de l’entreprise ou organisation ;
* secteur d’activité ;
* pays ;
* ville ;
* mot de passe ;
* confirmation du mot de passe ;
* acceptation des conditions.

Après validation :

* créer l’utilisateur ;
* créer l’organisation ;
* attribuer automatiquement l’utilisateur comme Super Administrateur ;
* créer un abonnement en statut En attente de paiement ;
* rediriger vers le paiement.

⸻

7. Appliquer la logique multi-organisation avec le même email

Le système doit permettre à un utilisateur utilisant le même email d’accéder à plusieurs organisations.

Cas attendu

Si l’email existe déjà dans Gameasu :

* ne pas bloquer l’inscription ;
* ne pas créer un doublon utilisateur ;
* permettre à cet utilisateur de créer ou rejoindre une nouvelle organisation ;
* rattacher cette nouvelle organisation à son compte existant ;
* lui attribuer le rôle Super Administrateur pour cette nouvelle organisation s’il en est le créateur ;
* afficher cette nouvelle organisation dans son sélecteur d’organisation après connexion.

Exemple

Un utilisateur avec issa@email.com peut déjà avoir accès à Organisation A.
S’il crée Organisation B avec le même email, le système doit :

* conserver le même compte utilisateur ;
* créer Organisation B ;
* associer issa@email.com à Organisation B ;
* donner le rôle Super Administrateur sur Organisation B ;
* permettre de choisir entre Organisation A et Organisation B après connexion.

⸻

8. Paiement obligatoire avant activation

Après l’inscription, le client ne doit pas avoir un accès complet immédiatement.

Statuts recommandés

* Compte créé
* Organisation créée
* Abonnement en attente de paiement
* Paiement en attente
* Paiement confirmé
* Abonnement actif

Tant que le paiement n’est pas confirmé :

* l’organisation existe ;
* le Super Administrateur existe ;
* l’accès complet aux modules est bloqué ;
* une page indique que le paiement est nécessaire ;
* le client peut reprendre le paiement.

⸻

9. Redirection vers le paiement

Après création du compte et de l’organisation, le bouton principal doit être :

Continuer vers le paiement

Le paiement doit reprendre automatiquement :

* formule choisie ;
* nombre d’utilisateurs ;
* périodicité ;
* montant total ;
* devise ;
* TVA ;
* code promo ou partenaire ;
* référence organisation ;
* référence client.

⸻

10. Résultat attendu

Je veux une page d’inscription ERP plus cohérente, plus premium et mieux alignée avec le parcours SaaS Gameasu.

La page doit :

* reprendre le design de la page login ;
* utiliser les mêmes couleurs, logo et style visuel ;
* supprimer le message “Aucune carte bancaire requise” ;
* remplacer “Choisir ma formule” par “Continuer vers le paiement” ;
* préremplir automatiquement le pack, le nombre d’utilisateurs et la périodicité ;
* permettre à un même email de créer ou rejoindre plusieurs organisations ;
* créer automatiquement le créateur comme Super Administrateur ;
* exiger le paiement avant activation complète ;
* synchroniser l’inscription, le paiement, l’ERP et le Cockpit.

Objectif final

Créer un parcours d’inscription professionnel où le client choisit sa formule sur le site web, arrive sur une page ERP déjà préremplie, crée son organisation, devient Super Administrateur, finalise le paiement, puis accède automatiquement aux modules inclus dans son pack.
