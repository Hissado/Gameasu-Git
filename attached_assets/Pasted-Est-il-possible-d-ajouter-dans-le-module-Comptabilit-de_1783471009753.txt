Est-il possible d’ajouter dans le module Comptabilité de Gameasu une section dédiée à la vérification des déclarations fiscales avant leur soumission définitive à l’administration fiscale ?

Objectif

Je veux créer un module intelligent de contrôle fiscal permettant aux entreprises de vérifier leurs déclarations avant dépôt, afin de réduire les erreurs, les oublis, les incohérences et les risques lors des contrôles fiscaux.

Ce module doit aider le client à identifier les points non conformes à la réglementation fiscale applicable avant de soumettre définitivement ses déclarations à l’OTR ou à l’administration fiscale compétente selon le pays.

⸻

1. Nom du module proposé

Ajouter une section dans :

Comptabilité > Vérification fiscale

ou

Comptabilité > Contrôle des déclarations fiscales

ou

Fiscalité > Prévalidation des déclarations

Nom recommandé :

Contrôle fiscal préalable

⸻

2. Fonctionnalités principales

Le module doit permettre de :

* filtrer tous les projets de déclarations fiscales ;
* consulter les déclarations en brouillon ;
* vérifier les montants déclarés ;
* détecter les incohérences ;
* identifier les points non conformes ;
* signaler les pièces justificatives manquantes ;
* comparer les déclarations avec les écritures comptables ;
* vérifier la cohérence entre TVA collectée, TVA déductible, ventes, achats et paiements ;
* générer une liste d’alertes avant soumission ;
* proposer des corrections ;
* valider la déclaration avant dépôt ;
* conserver une trace de toutes les vérifications.

⸻

3. Types de déclarations à contrôler

Prévoir une structure flexible pouvant s’adapter selon le pays et les obligations fiscales du client.

Exemples de déclarations possibles :

* TVA ;
* impôt sur les sociétés ;
* retenues à la source ;
* taxes sur salaires ;
* déclarations sociales si applicable ;
* acomptes fiscaux ;
* états récapitulatifs ;
* autres taxes locales ou sectorielles.

Le système ne doit pas être limité uniquement à l’OTR.
Il doit permettre de configurer l’administration fiscale selon le pays du tenant.

Exemples :

* OTR pour le Togo ;
* service des impôts selon le pays ;
* administration fiscale locale configurée dans les paramètres.

⸻

4. Détection des non-conformités

Le module doit identifier automatiquement les risques ou incohérences comme :

* montant de TVA incohérent avec les ventes ;
* TVA déductible sans justificatif ;
* facture fournisseur manquante ;
* numéro fiscal absent ;
* facture client non conforme ;
* écriture comptable non lettrée ;
* compte comptable mal utilisé ;
* déclaration incomplète ;
* période fiscale incorrecte ;
* doublon de déclaration ;
* différence entre chiffre d’affaires déclaré et chiffre d’affaires comptable ;
* dépenses non justifiées ;
* retenues non déclarées ;
* paiements non rapprochés ;
* anomalies dans les écritures ;
* dépassement de seuils fiscaux ;
* taux de taxe incorrect ;
* incohérence entre déclaration précédente et déclaration actuelle.

⸻

5. Système d’alertes

Chaque anomalie doit être classée par niveau de risque.

Niveaux recommandés

* Faible : point à vérifier ;
* Moyen : correction recommandée ;
* Élevé : risque fiscal important ;
* Bloquant : déclaration non prête à être soumise.

Exemple

Risque élevé : TVA collectée incohérente avec les ventes enregistrées sur la période.
Action recommandée : vérifier les factures clients du mois et les taux de TVA appliqués.

⸻

6. Workflow de vérification

Créer un workflow clair :

1. Création du projet de déclaration fiscale.
2. Import ou génération des données depuis la comptabilité.
3. Lancement du contrôle automatique.
4. Affichage des anomalies.
5. Correction des points non conformes.
6. Nouvelle vérification.
7. Validation interne.
8. Marquage comme prêt à soumettre.
9. Soumission ou export pour dépôt auprès de l’administration fiscale.
10. Archivage avec preuve et historique.

⸻

7. Correction avant soumission

Le système doit permettre de corriger les anomalies avant soumission.

Actions possibles

* ouvrir l’écriture comptable concernée ;
* corriger une facture ;
* ajouter une pièce justificative ;
* modifier une affectation comptable ;
* ajuster une période ;
* ajouter une note explicative ;
* marquer un point comme vérifié ;
* demander validation à un responsable ;
* relancer le contrôle après correction.

⸻

8. Score de conformité fiscale

Ajouter un score de conformité pour chaque déclaration.

Exemple

Score de conformité : 86 %

Avec une synthèse :

* 12 contrôles effectués ;
* 9 conformes ;
* 2 à corriger ;
* 1 bloquant.

La déclaration ne doit pas pouvoir être marquée comme prête à soumettre si des erreurs bloquantes existent.

⸻

9. Connexion avec les autres modules

Le module doit être connecté à :

* Comptabilité générale ;
* Comptabilité analytique ;
* Factures clients ;
* Factures fournisseurs ;
* Achats ;
* Ventes ;
* Paiements ;
* Encaissements ;
* Trésorerie ;
* Documents ;
* Rapports ;
* Paramètres fiscaux ;
* Utilisateurs & permissions.

Les contrôles doivent se baser sur les données réelles de l’organisation.

⸻

10. Paramètres fiscaux par pays

Créer une configuration fiscale flexible par tenant.

Paramètres à prévoir

* pays ;
* administration fiscale ;
* devise ;
* taux de TVA ;
* taux de retenue à la source ;
* calendrier fiscal ;
* échéances déclaratives ;
* seuils applicables ;
* types de taxes ;
* modèles de déclarations ;
* règles de contrôle ;
* pièces obligatoires ;
* comptes comptables concernés.

Important : les règles doivent être configurables, car elles varient selon les pays et peuvent évoluer.

⸻

11. Prévention des risques fiscaux

Le module doit aider à réduire les risques lors :

* des contrôles sur pièces ;
* des vérifications générales de comptabilité ;
* des audits fiscaux ;
* des demandes d’explication de l’administration ;
* des contrôles internes ;
* des revues comptables avant clôture.

L’objectif est de permettre au client de disposer d’un dossier propre, cohérent et justifié avant toute soumission.

⸻

12. Rapports et preuves

Après vérification, le système doit générer :

* rapport de contrôle fiscal ;
* liste des anomalies détectées ;
* corrections effectuées ;
* statut de conformité ;
* résumé des montants déclarés ;
* journal des validations ;
* pièces justificatives associées ;
* historique des versions ;
* export PDF ;
* export Excel.

Le rapport doit pouvoir être archivé dans les documents de l’organisation.

⸻

13. Permissions et sécurité

Ajouter des permissions spécifiques :

* voir les déclarations fiscales ;
* créer une déclaration ;
* lancer une vérification fiscale ;
* corriger les anomalies ;
* valider une déclaration ;
* soumettre une déclaration ;
* exporter les rapports fiscaux ;
* gérer les paramètres fiscaux ;
* voir les données fiscales sensibles.

Les données fiscales doivent être protégées, car elles sont sensibles.

⸻

14. Interface utilisateur

L’interface doit être claire et professionnelle.

Prévoir :

* liste des déclarations fiscales ;
* filtres par période, statut, type de déclaration et niveau de risque ;
* bouton Lancer la vérification ;
* tableau des anomalies ;
* score de conformité ;
* actions correctives ;
* historique des corrections ;
* bouton Marquer comme prêt à soumettre ;
* bouton Exporter le rapport de contrôle.

Statuts recommandés

* Brouillon ;
* En vérification ;
* Corrections requises ;
* Conforme ;
* Prêt à soumettre ;
* Soumis ;
* Archivé.

⸻

15. Résultat attendu

Je veux ajouter à Gameasu un module de vérification des déclarations fiscales capable de contrôler les projets de déclarations avant dépôt, détecter les non-conformités, proposer des corrections et sécuriser la soumission.

Objectif final

Permettre aux clients de Gameasu de réduire les risques fiscaux, préparer des déclarations plus fiables, mieux documenter leurs positions et disposer d’un dossier propre en cas de contrôle sur pièces ou de vérification générale de comptabilité.
