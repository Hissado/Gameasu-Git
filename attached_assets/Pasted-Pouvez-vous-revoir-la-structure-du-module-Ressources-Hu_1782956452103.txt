Pouvez-vous revoir la structure du module Ressources Humaines dans Gameasu afin qu’elle soit plus claire, plus logique et plus adaptée à un ERP multi-secteur ?

Actuellement, la section “Pointage & Paie BTP” donne l’impression que le module RH est principalement conçu pour le secteur BTP. Or, Gameasu est un ERP multi-secteur. Tous les clients n’auront pas besoin des mêmes règles de pointage, de paie ou de paramètres spécifiques au BTP.

L’objectif est donc de mieux organiser le module RH afin de permettre une utilisation simple, intuitive et adaptée à chaque type d’entreprise.

1. Revoir la structure générale du module RH

Au lieu d’avoir une section séparée appelée “Pointage & Paie BTP”, veuillez restructurer le module RH autour de sections principales plus universelles :

* Employés
* Présences
* Congés & Absences
* Paie
* Fiches de paie
* Contrats
* Départements & Postes
* Paramètres RH
* Rapports RH

Cette structure doit rester compréhensible pour tous les secteurs : BTP, commerce, restauration, services, ONG, cabinets, coopératives, industries, etc.

2. Placer la grille de pointage dans “Présences”

La grille de pointage ne doit pas être une section isolée appelée “Pointage & Paie BTP”.

Elle doit être intégrée dans la section :

Ressources Humaines → Présences

Dans cette section, l’utilisateur doit pouvoir gérer :

* le pointage journalier ;
* les heures d’arrivée et de départ ;
* les jours travaillés ;
* les retards ;
* les absences ;
* les heures supplémentaires ;
* les présences par chantier, projet, service ou département ;
* l’import/export des feuilles de pointage ;
* la validation des présences avant transmission à la paie.

Pour les entreprises du BTP, la présence peut être associée à un chantier ou à une équipe terrain. Pour les autres secteurs, elle peut être associée à un département, un service, une agence ou un site.

3. Placer les états de salaires dans “Fiches de paie”

Les états de salaires doivent être intégrés dans la section :

Ressources Humaines → Paie → Fiches de paie

Cette section doit permettre de générer la fiche de paie finale à partir des informations synchronisées :

* données employé ;
* contrat ;
* salaire de base ;
* présences validées ;
* absences ;
* congés payés ;
* heures supplémentaires ;
* primes ;
* retenues ;
* avances ;
* cotisations ;
* net à payer.

La fiche de paie finale doit être automatiquement synchronisée avec les données de présence, de congés, d’absences et de paramètres de paie.

4. Déplacer les paramètres BTP dans les paramètres RH

Les paramètres BTP ne doivent pas apparaître comme un module principal pour tous les clients.

Ils doivent être placés dans :

Ressources Humaines → Paramètres RH → Paramètres sectoriels → BTP

Cette section doit uniquement être visible ou activée pour les entreprises qui utilisent le secteur BTP.

Les paramètres BTP peuvent inclure :

* chantiers ;
* équipes terrain ;
* catégories d’ouvriers ;
* pointage par chantier ;
* primes de chantier ;
* indemnités de déplacement ;
* règles spécifiques aux heures supplémentaires ;
* calculs propres au personnel terrain ;
* rapports de présence par chantier.

5. Prévoir une logique multi-secteur

Gameasu doit permettre d’activer ou désactiver certaines fonctionnalités RH selon le secteur d’activité du tenant.

Proposer une architecture basée sur des paramètres sectoriels activables.

Exemple :

Paramètres RH → Paramètres sectoriels

* BTP
* Commerce
* Restauration
* Services
* ONG
* Cabinet / Conseil
* Industrie
* Logistique
* Éducation
* Santé

Chaque secteur peut avoir ses propres règles, mais la structure principale du module RH doit rester universelle.

6. Créer une logique de modules RH activables

Tous les clients ne doivent pas voir les fonctionnalités dont ils n’ont pas besoin.

Veuillez prévoir un système où chaque tenant peut activer ou désactiver :

* pointage simple ;
* pointage avancé ;
* pointage par chantier ;
* pointage par site ;
* paie simple ;
* paie avancée ;
* fiches de paie ;
* congés payés ;
* absences ;
* primes ;
* avances ;
* retenues ;
* paramètres sectoriels BTP ;
* rapports RH avancés.

L’objectif est d’éviter une interface trop chargée et de rendre le module RH plus simple à utiliser.

7. Synchronisation entre Présences, Congés et Paie

Le système doit assurer une synchronisation automatique entre :

Présences → Congés & Absences → Paie → Fiches de paie

La logique doit être la suivante :

1. Les employés sont créés dans la fiche employé.
2. Les contrats et salaires sont renseignés.
3. Les présences sont saisies ou importées.
4. Les absences et congés sont validés.
5. Les données validées sont envoyées vers la paie.
6. La fiche de paie est générée automatiquement.
7. Les rapports RH et exports Excel/PDF sont produits.

Aucune donnée ne doit être saisie plusieurs fois inutilement.

8. Proposition de structure finale recommandée

Veuillez organiser le module RH de cette façon :

Ressources Humaines

1. Tableau de bord RH
    * effectif total ;
    * présences du jour ;
    * absences ;
    * congés en attente ;
    * paies à préparer ;
    * alertes RH.
2. Employés
    * liste des employés ;
    * fiche employé ;
    * documents ;
    * contrats ;
    * historique.
3. Présences
    * grille de pointage ;
    * pointage journalier ;
    * pointage par période ;
    * pointage par site, chantier ou département ;
    * validation des présences ;
    * import/export Excel.
4. Congés & Absences
    * demandes de congés ;
    * validation ;
    * soldes de congés ;
    * absences justifiées ;
    * absences non justifiées.
5. Paie
    * préparation de la paie ;
    * variables de paie ;
    * primes ;
    * retenues ;
    * avances ;
    * validation de la paie.
6. Fiches de paie
    * génération des fiches de paie ;
    * historique ;
    * export PDF ;
    * export Excel ;
    * envoi aux employés si nécessaire.
7. Rapports RH
    * rapport de présence ;
    * rapport des absences ;
    * rapport des congés ;
    * rapport de paie ;
    * rapport par chantier, site, département ou projet.
8. Paramètres RH
    * règles de présence ;
    * règles de paie ;
    * jours ouvrables ;
    * jours fériés ;
    * types de congés ;
    * types de primes ;
    * types de retenues ;
    * paramètres sectoriels ;
    * paramètres BTP si activés.

9. Objectif final

L’objectif final est d’avoir un module RH clair, simple et professionnel, adapté à un ERP multi-secteur.

La section Pointage & Paie BTP doit être remplacée par une structure plus universelle :

* la grille de pointage doit être dans Présences ;
* les états de salaires doivent être dans Paie / Fiches de paie ;
* les paramètres BTP doivent être dans Paramètres RH → Paramètres sectoriels ;
* les règles spécifiques au BTP doivent être activables uniquement pour les entreprises concernées ;
* la fiche de paie finale doit rester centralisée, synchronisée et générée automatiquement à partir des données RH validées.

Veuillez proposer et implémenter la meilleure structure possible pour que le module RH soit facile à utiliser, propre, évolutif, multi-secteur et prêt pour une utilisation réelle par différents types d’organisations.
